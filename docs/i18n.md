# Weather localization

The Android application ID and Kotlin namespace are `org.fundamentalos.weather`.
The default app label is **Weather**, localized as Wetter, Météo, Pogoda, Погода,
and 天气. Changing the application ID creates a separate Android app identity;
it does not upgrade or migrate private data from `ink.duo3.caelum`.

## Resources and language selection

`app/src/main/res/values/strings.xml` is the English fallback. `values-en`,
`values-de`, `values-fr`, `values-pl`, `values-ru`, and `values-zh` contain complete
translations. Explicit English resources allow English to take precedence over
secondary device languages. `xml/locales_config.xml` exposes these six languages
in Android 13+ application language settings. Older Android versions follow the
device language.

Use `stringResource` / `pluralStringResource` in Compose. Callbacks can capture
`LocalResources.current`; do not cache rendered text across configuration changes.
Use numbered placeholders, keep complete sentences in resources, and include all
plural categories required by a language. Decimal day durations use Android ICU
measure formatting. Add every new localizable resource to every language and run
`python3 tools/check_i18n.py`.

The ViewModel stores status resource IDs and ISO forecast dates/times. Display
formatting happens in `ui/text/WeatherText.kt`, using the activity configuration,
the device time zone and its 12/24-hour preference. Weather condition codes,
compass directions, moon phases, AQI categories, and known map layer IDs resolve
locally. Protocol codes and diagnostic logs are not translated. Chinese strings
in provider warning parsers are input syntax, and preview fixtures intentionally
include sample Chinese data.

## Provider text

QWeather requests include the selected language. Its documented language fallback
and exceptions apply: https://dev.qweather.com/en/docs/resource/language/.
FundamentalOS currently exposes Chinese and English narrative text, so requests
use Chinese for Chinese locales and English otherwise. Its conditions and wind
labels are translated locally from their codes/degrees. Provider-authored AQI
explanations, precipitation summaries, warning titles/bodies, geographical names,
and future unknown map layers retain the provider response. Full localization of
those free-form fields requires corresponding provider translations; the app does
not machine-translate official warning text. A retained ViewModel refreshes
provider data after the app language changes.

## Verification

- `python3 tools/check_i18n.py`: complete resource sets, numbered placeholders,
  required plural forms, and duplicate resource detection.
- `./gradlew assembleDebug`: build application and merged resources.
- `./gradlew testDebugUnitTest --tests '*ProviderLanguageTest' --tests '*ExampleUnitTest'`:
  provider language mapping and the existing offline smoke test.
- `./gradlew connectedDebugAndroidTest`: application identity, six localized names,
  Russian/Polish plural forms, and Compose reconfiguration without refetching data.
- `./gradlew lintDebug`: includes Android translation and format-string checks.

Full lint reports pre-existing errors in `NoFallbackLineSpacingPatch.java`
(internal API opt-in) and `WeatherApp.kt` (`remember` returning `Unit`); neither
is a localization error.
